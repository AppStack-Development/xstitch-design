## สรุป

หน้าใหม่ที่ทุกคนเข้าไปดูลายที่คนอื่นแชร์ได้ โดยไม่ต้องเข้าสู่ระบบ กด “ลองปัก” หรือ “แก้ไขเป็นสำเนาของฉัน” ได้ทันที
คนที่เข้าสู่ระบบแล้วแชร์ลายของตัวเองได้จากหน้าแก้ไขลาย

**ทำไมคุ้ม**

- แก้ปัญหา “จะปักอะไรดี” ของมือใหม่ เลือกลายคนอื่นแล้วเริ่มปักได้เลย ไม่ต้องแปลงรูปหรือออกแบบเอง
- ให้เหตุผลกลับมาใช้ซ้ำ (ตอนนี้คนมาทำลาย 1 ลายแล้วก็ไป)
- ต้นทุนต่ำ: ลายหนึ่งลายเป็นข้อมูลบีบอัดไม่กี่ KB และรูปตัวอย่างวาดในเบราว์เซอร์เอง ไม่ต้องเก็บไฟล์รูป

**รอบแรกไม่ทำ** (ไว้รอบถัดไป ถ้ามีคนใช้จริง): รูปงานที่ปักเสร็จ ความเห็น หน้าโปรไฟล์ ติดตามคน ขายลาย การแข่งขันตามเทศกาล

## 1. ตัดสินใจว่าจะทำไหม

ใช้คำถามข้อ 6–7 ในแผนทดสอบรอบ 2

- ข้อ 6 (จะเข้าไปหาลายจากหน้านี้ก่อนทำเอง) เฉลี่ยอย่างน้อย **3.5**
- มีอย่างน้อย **3 คน** ให้ข้อ 7 (จะแชร์ลายของตัวเอง) ตั้งแต่ **4** ขึ้นไป

ถ้าผ่านทั้งสองข้อ เริ่มทำรอบแรก ถ้าคนอยากดูแต่ไม่อยากแชร์ ให้ดูเหตุผลก่อน (เช่น กลัวโดนก๊อป ไม่มั่นใจในงาน)
แล้วค่อยปรับแบบ เช่น เริ่มจากลายที่ทีมคัดมาเองก่อน

## 2. ผู้ใช้ทำอะไรได้

| ใคร | ทำอะไรได้ |
|---|---|
| ทุกคน (ไม่ต้องเข้าสู่ระบบ) | ดูรายการลาย กรองผ้า/3D ความยาก เรียงล่าสุด/หัวใจมากสุด · เปิดดูลาย · “ลองปัก” · “แก้ไขเป็นสำเนาของฉัน” · แจ้งปัญหา |
| คนที่เข้าสู่ระบบ | ทุกอย่างข้างบน · กดหัวใจ · แชร์ลายของตัวเอง · แก้ชื่อ/คำอธิบาย · ถอนลายออก |
| ทีมงาน | ซ่อน/ลบลายที่ถูกแจ้ง (รอบแรกทำผ่าน Supabase Table Editor ยังไม่ต้องมีหน้าแอดมิน) |

**การแชร์ (จากหน้าแก้ไขลาย → เมนูส่งออก/แชร์ → “แชร์ในชุมชน”)**

1. ถ้ายังไม่เข้าสู่ระบบ ชวนเข้าสู่ระบบก่อน (ใช้หน้าบัญชีเดิม รวมถึงข้อความสำหรับเบราว์เซอร์ใน LINE)
2. ครั้งแรกให้ตั้ง **ชื่อที่แสดง** (นามแฝงได้ ไม่ใช้ชื่อจาก Google อัตโนมัติ)
3. กรอกชื่อลาย คำอธิบายสั้น ๆ แท็ก (เลือกจากรายการ เช่น สัตว์ ดอกไม้ ตัวอักษร เทศกาล) ระบบเติมความยาก จำนวนสี ขนาดให้เอง
4. ติ๊กยืนยัน “ฉันออกแบบลายนี้เอง หรือมีสิทธิ์แชร์” แล้วกดแชร์
5. ได้ลิงก์ของลายในชุมชน คัดลอกไปส่งต่อได้

**ลายที่แชร์แล้วเป็นภาพ ณ ตอนนั้น** แก้ลายในเครื่องต่อได้โดยไม่กระทบของที่แชร์ ถ้าอยากอัปเดตให้กด “แชร์เวอร์ชันใหม่” ทับของเดิม

**ไม่แชร์:** ความคืบหน้าการปัก รายการด้ายของฉัน หรือรูปต้นฉบับที่ใช้แปลงเป็นลาย

**สำเนาและเครดิต:** “แก้ไขเป็นสำเนาของฉัน” สร้างลายในเครื่องที่จำว่ามาจากลายไหน ถ้าเอาไปแชร์ต่อ หน้าลายจะแสดง “ดัดแปลงจาก … โดย …” ให้อัตโนมัติ

## 4. ข้อมูล (Supabase)

ไฟล์ใหม่ `supabase/migrations/0003_community.sql` (ร่าง):

```sql
-- public identity, separate from the Google name in profiles
create table public.creators (
  user_id uuid primary key references auth.users (id) on delete cascade,
  handle text not null unique check (handle ~ '^[a-z0-9_]{3,24}$'),
  display_name text not null check (char_length(display_name) between 1 and 40),
  created_at timestamptz not null default now()
);

create table public.posts (
  id text primary key default substr(md5(random()::text), 1, 10),
  author uuid not null references auth.users (id) on delete cascade,
  title text not null check (char_length(title) between 1 and 80),
  description text check (char_length(description) <= 1000),
  base text not null check (base in ('aida', 'print3d')),
  difficulty text not null check (difficulty in ('easy', 'medium', 'hard')),
  colors smallint not null,
  stitches int not null,
  cols smallint not null, rows smallint not null,
  tags text[] not null default '{}',
  data text not null check (char_length(data) <= 200000), -- encodeShare(): no progress, deflated
  remix_of text references public.posts (id) on delete set null,
  status text not null default 'published' check (status in ('published', 'hidden', 'removed')),
  like_count int not null default 0,
  report_count int not null default 0,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
create index posts_feed on public.posts (status, created_at desc);
create index posts_popular on public.posts (status, like_count desc);

create table public.post_likes (
  post_id text references public.posts (id) on delete cascade,
  user_id uuid references auth.users (id) on delete cascade,
  created_at timestamptz not null default now(),
  primary key (post_id, user_id)
);

create table public.post_reports (
  id bigint generated always as identity primary key,
  post_id text not null references public.posts (id) on delete cascade,
  reporter uuid references auth.users (id) on delete set null, -- null = signed out
  reason text not null check (reason in ('copyright', 'inappropriate', 'spam', 'other')),
  note text check (char_length(note) <= 1000),
  created_at timestamptz not null default now()
);
```

**สิทธิ์ (RLS)**

- `posts`: ทุกคนอ่านได้เฉพาะ `status = 'published'` · เจ้าของอ่าน/แก้ของตัวเองได้ทุกสถานะ แต่เปลี่ยน `status`, `like_count`, `report_count` เองไม่ได้ (ใช้ column grants แบบตาราง feedback)
- `creators`: ทุกคนอ่านได้ · แก้ได้เฉพาะของตัวเอง
- `post_likes`: เพิ่ม/ลบได้เฉพาะของตัวเอง · trigger ปรับ `like_count`
- `post_reports`: เพิ่มได้อย่างเดียว (เหมือน feedback) · trigger เพิ่ม `report_count` และ **ซ่อนอัตโนมัติ** (`hidden`) เมื่อถูกแจ้งจาก 3 คนขึ้นไป รอทีมงานตรวจ
- กันสแปม: แชร์ได้ไม่เกิน 10 ลายต่อวันต่อบัญชี (ตรวจใน trigger)
- `delete_my_account()` เดิมลบทุกอย่างตามไปด้วย (cascade) ลายที่คนอื่นดัดแปลงต่อยังอยู่ แต่เครดิตต้นฉบับหายไป

**ขนาดและค่าใช้จ่ายบนแพ็กเกจฟรี**

- ลายหนึ่งลายหลังบีบอัด (`encodeShare`) ประมาณ 1–5 KB ฐานข้อมูล 500 MB รองรับได้เกินแสนลาย
- หน้ารายการโหลด 24 ลาย ≈ 50–120 KB ต่อครั้ง ถ้าโควตาส่งข้อมูลรายเดือนอยู่ที่ราว 5 GB จะรองรับได้ประมาณ 40,000 ครั้งต่อเดือน
  ก่อนเปิดจริงให้เช็กโควตาปัจจุบันของ Supabase อีกครั้ง และใส่ cache ฝั่งเบราว์เซอร์/service worker ให้หน้ารายการ
- รูปงานที่ปักเสร็จ (รอบถัดไป) ใช้พื้นที่เก็บไฟล์จริง ต้องย่อเป็น WebP ราว 150 KB ก่อนอัปโหลด

## 5. ความเป็นส่วนตัว (PDPA)

- หน้าชุมชนแสดงแค่ **ชื่อที่แสดง** ที่ผู้ใช้ตั้งเอง ไม่แสดงอีเมลหรือรูปโปรไฟล์ Google
- ถอนลายแล้วลบข้อมูลลายจริง (ไม่ใช่แค่ซ่อน) · ลบบัญชีแล้วลบทุกลายที่แชร์
- อัปเดตนโยบายความเป็นส่วนตัว: เพิ่มหัวข้อ “เนื้อหาที่คุณแชร์เป็นสาธารณะ” (อะไรถูกแสดง ใครเห็นได้ ลบอย่างไร) และเพิ่มข้อมูลชุมชนในไฟล์ “ดาวน์โหลดข้อมูลของฉัน”
- เด็กอายุต่ำกว่า 10 ปีต้องได้รับความยินยอมจากผู้ปกครองตาม PDPA ระบุในข้อกำหนดว่าผู้แชร์ต้องอายุ 10 ปีขึ้นไป หรือได้รับอนุญาตจากผู้ปกครอง

## 6. ลิขสิทธิ์และเนื้อหา

- ต้องติ๊กยืนยันว่าออกแบบเองหรือมีสิทธิ์แชร์ทุกครั้ง
- **การใช้ลายที่แชร์ (รอบแรกมีแบบเดียว ไม่ให้เลือก):** ใช้ส่วนตัวและดัดแปลงได้ ต้องให้เครดิต ห้ามใช้เชิงพาณิชย์ (เทียบได้กับ CC BY-NC 4.0) แสดงสั้น ๆ ใต้ลายทุกลาย
- ลายตัวการ์ตูนที่มีลิขสิทธิ์มีโอกาสถูกแชร์สูง ต้องมีหน้า **ข้อกำหนดการใช้งาน** และช่องทางแจ้งลบ (อีเมล admin@appstack-dev.io + ปุ่มแจ้งปัญหา) ตอบภายใน 7 วัน
- เหตุผลการแจ้ง: ละเมิดลิขสิทธิ์ · ไม่เหมาะสม · สแปม · อื่น ๆ

## 9. ลำดับงานรอบแรก (ประมาณ 1.5–2 วัน)

1. Migration + RLS + triggers ทดสอบสิทธิ์ทุกแบบ (ไม่เข้าสู่ระบบ / เจ้าของ / คนอื่น) — ครึ่งวัน
2. `src/lib/community.ts`: list (แบ่งหน้า กรอง เรียง) · get · publish/update/unpublish · like · report — ใช้ client เดิมใน `cloud.ts`
3. หน้า `#/community`, `#/c/<id>`, การ์ดบนหน้าแรก — นำ `Thumb`, การ์ดลายตัวอย่าง, รายการด้ายจาก QuickCreate มาใช้ซ้ำ
4. กล่องแชร์ในหน้าแก้ไขลาย + ตั้งชื่อที่แสดง + “ลายที่ฉันแชร์” ในหน้าบัญชี
5. ข้อกำหนดการใช้งาน + อัปเดตนโยบายความเป็นส่วนตัว + ข้อความ TH/EN ครบ
6. ตรวจ UI ทุกขนาดจอ · แชร์ลายตัวอย่าง 8 ลาย · deploy

## 10. คำถามที่ยังเปิดอยู่ (ตอบจากผลทดสอบรอบ 2)

- คนอยากเห็นรูปงานที่ปักเสร็จจริงมากแค่ไหน ถ้ามาก ควรย้ายขึ้นมาทำในรอบแรก
- ชื่อจริงหรือนามแฝง (ตอนนี้ออกแบบให้ใช้ชื่อที่แสดงที่ตั้งเอง)
- ใครเป็นคนดูการแจ้งปัญหา และบ่อยแค่ไหน
- ควรให้ดาวน์โหลด STL ของลาย 3D คนอื่นได้ทันที หรือให้เปิดเป็นสำเนาก่อน
